## 防双响：让「压哪一边」可配置，并把「同一台设备」判得更准

现状（0.6.1）：

- 开关只在「网页响铃 + 宿主提醒」都开着时出现，**默认关**；
- 判定「同一台设备」看页面地址：`localhost` / `127.0.0.1` / `::1` 算本机，其余（机器名、局域网 IP）算另一台设备；
- 开启后**压掉浏览器**，只留宿主那一声；宿主没接管（宿主关着、或该事件是「关」）时浏览器照常响；
- 宿主「发出了声」这件事现在会看能力位：`capBeep` / `capNotify` 为 false 时不再压浏览器（已有回归测试）。

待办：

1. **「压宿主」目前做不到。** 宿主是在自己的 `record()` 里发声/弹 toast 的，客户端没法撤掉。
   要支持得加一条宿主设置（例如 `dedupeSide`），再让宿主在发声前判断「这台机器上是不是有个
   本机客户端已经响过了」。多客户端（电脑 + 手机同时开着页面）时，还要能区分是哪个客户端提的。
2. **同机判定可以更准。** 页面经机器名或局域网 IP 打开时按「另一台设备」处理（宁可多响一声）。
   给 sysget 加 `hostName`（`os.hostname()`）只能解决「本机用机器名访问」，**解决不了反向误判**：
   经端口转发把远端 `127.0.0.1` 映射到本机时，页面地址仍是 localhost。要根治得让宿主回报
   一个「这台机器上的浏览器实例」标识（例如页面加载时宿主下发一次性 token，宿主发声时带同 token），
   或干脆把去重交给宿主判断。
3. **设置页多标签页同步只做了合并，没做冲突合并**：现在监听 `storage` 后整体重载，两个标签页
   同时改同一项时以后写者为准。
